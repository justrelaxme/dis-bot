# Dis-bot

Discord-бот игрового сообщества. Модульный монолит на TypeScript.

Дизайн: [docs/superpowers/specs/2026-07-27-discord-gaming-bot-design.md](docs/superpowers/specs/2026-07-27-discord-gaming-bot-design.md)

## Что умеет бот

**Привязки и роли**

| Команда | Кому | Что делает |
|---|---|---|
| `/ping` | всем | задержка шлюза, проверка что бот жив |
| `/link steam\|riot\|valorant` | игроку | привязать игровой аккаунт с подтверждением владения |
| `/unlink` | игроку | убрать привязку и снять выданные за неё роли |
| `/profile` | игроку | карточка: привязки, ранги, изменения за месяц |
| `/card on` \| `off` | игроку | открыть или закрыть свою страницу на сайте `/p/<id>`: турниры, титулы, сезон, достижения. Ранги и игровые ники — отдельными переключателями, оба по умолчанию выключены |
| `/ranksync` | игроку | обновить свои ранги сейчас, не дожидаясь получаса |
| `/rolemap` | администратору | «Diamond в LoL — вот эта роль» и просмотр настроенного |

Ранги обновляются сами каждые полчаса. При смене тира или дивизиона роли перевыдаются
автоматически. Неподтверждённая привязка авто-роль не даёт.

**Турниры**

| Команда | Кому | Что делает |
|---|---|---|
| `/tournament schedule` | организатору | настроить ежедневный автомат: времена, режим, состав |
| `/tournament poll` | организатору | голосование по дисциплине вручную |
| `/tournament create` | организатору | создать турнир и открыть регистрацию |
| `/tournament start` | организатору | закрыть регистрацию, разложить сетку, создать комнаты. Не нажали — турнир стартует сам во время, указанное на панели |
| `/tournament settings` | администратору | роль организаторов и канал штаба: кого и куда звать на споры и сбои |
| `/tournament cancel` \| `info` | организатору | отменить турнир с уборкой комнат; текущее состояние |
| `/team create` \| `leave` \| `roster` | игроку | собрать команду карточкой с кнопкой «Вступить», выйти, состав |
| `/team add` \| `kick` | капитану | замена в составе — работает и во время турнира |
| `/checkin` | капитану | отметить состав. **Не отметились — в сетку не попадёте** |
| `/match report` | игроку | заявить результат: «мы выиграли» или «мы проиграли» |
| `/match resolve` \| `walkover` | организатору | решить спорный матч; победа без игры при неявке. Может и роль организаторов. Номер матча и победитель подсказываются |
| `/match correct` | организатору | исправить закрытый результат, пока следующий матч не начался |
| `/predict board` \| `mine` | всем | лучшие прогнозисты; свои прогнозы по идущему турниру |
| `/cast` | организатору | сцена трансляции для «Демонстрации экрана» и личный пульт к ней — см. `docs/stream.md` |
| `/stats` | всем | турнирный след: титулы, матчи, последние турниры |

**Матч от карточки до итога.** Когда матч становится играбельным, в его ветке появляется
карточка: кто играет (с упоминаниями), голосовые, драфт и кнопка **«На месте»**. Когда её
нажали обе стороны, матч начинается — только тогда идёт таймер драфта. Не нажали за десять
минут — организатор получает в штабе кнопки «Техпобеда», «Подождать», «Начать без отметки».

Соперник подтверждает результат кнопкой или жмёт «Не так было» и пишет причину — спор с
кнопками решения («Принять», «Отдать сопернику», «Переиграть») приходит в канал штаба с
упоминанием организаторов (задать: `/tournament settings`). Молчит час — результат
принимается сам; за 15 минут до этого сопернику напоминают.

**Прогнозы — кнопками.** На старте турнира под каналом объявлений появляется публичная ветка
«Прогнозы», и на каждый матч в ней — карточка с кнопками «За A» / «За B» и живым раскладом
голосов. Приём закрывается, когда матч начался. Угадавшие получают монеты; отмена турнира
прогнозы аннулирует, исправление результата пересчитывает.

**Результат Dota можно не подтверждать вручную.** Если при `/match report` указать
`dota_match:<ID матча>`, бот сам посмотрит OpenDota: узнает игроков обеих команд по
привязкам Steam, определит стороны и сверит с исходом. Совпало — матч закрыт сразу.
Противоречит — заявка не принимается. Проверка часто невозможна, потому что Dota по
умолчанию не показывает игроков публичных матчей, — тогда работает обычный путь.

**Формат сетки выбирается.** По умолчанию у турнира от организатора — двойное устранение:
проигравший падает в нижнюю сетку и может дойти до финала оттуда, выбывание только со
второго поражения. У ежедневного автомата по умолчанию выбывание с первого: двойное
примерно удваивает длину вечера (восьми командам нужно шесть волн матчей вместо трёх).

Жеребьёвка идёт по **средней** силе состава из рангов привязок: команда с одним сильным
игроком не должна забирать пропуск незаслуженно. Пропуски в неполной сетке достаются
старшим сеяным, а первый со вторым сеяным встречаются не раньше финала.

Каждой команде создаётся приватный голосовой канал, каждому матчу — ветка, куда пускает
обе команды пары (каналы команд друг друга не видят, а о лобби договориться надо).
После турнира каналы удаляются, ветки архивируются.

**Между турнирами**

| Команда | Кому | Что делает |
|---|---|---|
| `/season table` | всем | таблица сезонной серии |
| `/season start name:` | организатору | начать сезон: с этого момента каждый доигранный турнир приносит очки |
| `/season close crown: champion:` | организатору | закрыть сезон: чемпион — в зал славы, роль-корона переезжает к нему. Корону выбирает тот, у кого есть «Управление ролями», и только роль ниже своей. `champion:` — только при ничьей на первом месте |

**Сезонная серия.** Каждый доигранный турнир начисляет очки всем, кто играл: по одному за
каждого, кого игрок оставил позади, одно за участие и пять сверху за титул. В командном
турнире очки получает каждый в составе. Таблица — `/season table` и страница `/season`.
Пока сезон не начат, очки не начисляются. Равные по очкам, титулам и лучшему месту делят
место в таблице; если так делят первое, бот чемпиона сам не назначает — организатор решает,
как выбрать (например, матчем), и закрывает сезон с `champion:`. Потерянное начисление (сбой
базы, перезапуск в момент финала) раз в десять минут догоняет страховочная джоба. Это отдельно
от сезонов прогрессии: там опыт за общение, здесь спорт.

**Итог недели** выходит сам в понедельник после полудня (часовой пояс расписания) в канал
объявлений: чемпионы, у кого серия титулов, апсет недели, самые частые пики и баны,
прогнозист недели, лидеры сезона. Нет турниров за неделю — нет итога.

**Личные встречи.** В карточке «матч готов» и на табло трансляции — счёт прошлых встреч пары
(у команд — по капитанам, и только командных; у одиночек — только одиночных). Техническая
победа при неявке и отменённые турниры не в счёт. От трёх встреч с разницей не больше одной —
«Соперничество».

**Прогрессия**

| Команда | Кому | Что делает |
|---|---|---|
| `/rank` | игроку | уровень, опыт, монеты, достижения, место в таблице |
| `/top` | всем | лидерборд сезона |
| `/shop` | игроку | магазин: посмотреть и купить за монеты |
| `/progression` | администратору | роли за уровень, товары, новый сезон, награды за сезон, ручное начисление |

Опыт идёт за сообщения и за время в голосовых, монеты — за уровни. Антифарм в трёх местах:
пауза между начислениями живёт в Redis (после перезапуска флуд не продолжить), сообщения
короче трёх символов не считаются, а опыт за голос даётся только если в канале был кто-то
ещё и не больше четырёх часов за сессию.

Сезон обнуляет зачёт, но не историю: журнал начислений и достижения остаются. **Закрытие
сезона награждает призовые места:** монеты, достижение и роль чемпиона. Награда настраивается
одним множителем — `/progression season-rewards places:3 coins:100` даёт 300, 200 и 100 монет
за первые три места. Роль чемпиона переезжает к новому, а постоянный след оставляет
достижение: обнуление без награды — это просто потеря прогресса.

**Поиск тиммейтов**

| Команда | Кому | Что делает |
|---|---|---|
| `/lfg post` | игроку | объявить сбор: игра, сколько людей, режим, заметка |
| `/lfg list` \| `close` | игроку | кто сейчас собирает; закрыть свой сбор |
| `/lfg roles` | игроку | подписки: о каких сборах упоминать. Роли снимаются и надеваются самим |
| `/lfg-setup` | администратору | канал сборов и роль для упоминаний по игре |

Люди записываются кнопкой на карточке. Когда состав набран, бот сам создаёт голосовой канал
с правами только на этот состав и лимитом мест. У сбора есть срок — истёкшие закрываются
сами: объявление, висящее сутки, хуже отсутствия объявления.

**Встреча новичков**

| Команда | Кому | Что делает |
|---|---|---|
| `/start` | всем | один следующий шаг именно для тебя |
| `/welcome here` \| `off` \| `test` | администратору | встречать новичков в этом канале; выключить; посмотреть, как это выглядит |
| `/welcome config` | администратору | роль при входе, каналы правил и турниров, своя первая строка, писать ли в личку |

Человек заходит на сервер — бот здоровается в канале короткой карточкой с одной кнопкой и
пишет в личку разбор: чего именно **этому** человеку не хватает, чтобы участвовать. Порядок
проверок повторяет порядок, в котором новичок упирается в препятствия: нет привязки → нет
команды → состав не отмечен. Называется ровно один шаг, потому что список из десяти команд
читают тем меньше, чем он длиннее.

**Модерация**

| Команда | Кому | Что делает |
|---|---|---|
| `/mod warn` \| `mute` \| `unmute` | модератору | предупредить, заглушить, снять |
| `/mod history` \| `lift` | модератору | история нарушений; снять запись |
| `/ticket open` \| `close` | игроку | приватная ветка с модераторами; закрыть — автору или модератору, кнопкой или командой |
| `/guard` | администратору | пороги антиспама и антирейда, канал журнала |

Любое действие сначала попадает в свой журнал, потом в Discord: Discord историю не хранит, и
без журнала «предупреждали ли его раньше» — вопрос к памяти модератора. Снятие наказания не
удаляет запись, а помечает её снятой.

Антиспам ловит скорость, копипасту и массовые упоминания, и **не трогает модераторов**.
Антирейд поднимает тревогу, но никого не банит сам: автоматический бан на волне заходов
однажды выкосит наплыв настоящих людей, и отменить это будет нечем.

## Ежедневный автомат

Настраивается одной командой **в том канале, где должны появляться объявления**:

```
/tournament schedule enabled:true poll_at:14:00 start_at:20:00 mode:team team_size:5
```

Дальше бот ведёт день сам: в 14:00 вывешивает голосование по дисциплине, по его итогу
объявляет условия участия и открывает регистрацию, в 20:00 раскладывает сетку и создаёт
комнаты. Времена — в часовом поясе из настройки (по умолчанию `Europe/Berlin`).

Автомат сам себя останавливает, если три дня подряд никто не отметился, и не начинает
новый день, пока не закрыт предыдущий турнир. Выключить: `enabled:false`.

## Витрина

Сайт поднимается тем же процессом на `HTTP_PORT`:

| Адрес | Что показывает |
|---|---|
| `/` | список турниров |
| `/t/:id` | сетка: круги, пары, победители, состояние матчей, номер матча и ссылка на драфт. При двойном устранении — верхняя, нижняя и гранд-финал. **Обновляется сама**, без F5 |
| `/hall` | зал славы: доигранные турниры, чемпионы, титулы по названию команды |
| `/leaderboard/:game` | таблица по рангам, только подтверждённые привязки |
| `/cast/t/:id` | сцена трансляции 16:9 для Go Live: отсчёт, сетка, драфт, табло, пьедестал — переключается сама |
| `/season` | таблица сезонной серии |
| `/p/:id` | карточка игрока — **только если игрок сам открыл её** командой `/card on` |

Сетка идущего турнира и драфт обновляются сами: бот шлёт открытым страницам сигнал через
`/api/live/t/:id` (Server-Sent Events), и страница перечитывает себя. Без JavaScript всё
работает как раньше — по F5. За прокси с буферизацией (nginx) нужен `proxy_buffering off`
для `/api/live/`; Caddy из compose этот путь не сжимает.

Страница игрока закрыта, пока он сам её не откроет: связка Discord-аккаунта с игровым —
личные данные. `/card on` открывает турнирный след, сезон и достижения; ранги — с
`ranks:true`, игровые ники — с `accounts:true`. Ранг без ника — не анонимность: лидерборд
показывает ник рядом с рангом, и бот об этом предупреждает. `/card off` закрывает страницу
сразу: согласие проверяется на каждый запрос, мимо кэша. Ушедший с сервера закрыть её уже
не может, поэтому страница пропадает сама. Поисковикам она не отдаётся (`noindex`). Лидерборд показывает игровой ник и ранг, которые игрок и так публикует в самой
игре, а зал славы — командные результаты, то есть публичные события сервера.

Посмотреть оформление до запуска бота, без токена Discord:

```bash
npx tsx scripts/web-demo.ts     # поднимает витрину с наполненной сеткой на localhost:3000
```

## Запуск на сервере

### 1. Приложение Discord

[Developer Portal](https://discord.com/developers/applications) → **New Application**.

- вкладка **Bot** → **Reset Token**, скопировать — это `DISCORD_TOKEN`;
- там же включить **оба** привилегированных интента: **Server Members Intent** и
  **Message Content Intent**. Без них Discord отклонит подключение с «Used disallowed
  intents» — бот запрашивает их в коде. Members нужен для выдачи ролей и встречи
  новичков, Message Content — для антиспама и опыта за сообщения: без текста сообщения
  повторы и упоминания считать нечем;
- вкладка **General Information** → **Application ID** — это `DISCORD_APP_ID`;
- вкладка **OAuth2** → **URL Generator** → scopes `bot` и `applications.commands`, права
  `Manage Roles` и `Send Messages` → открыть ссылку и добавить бота на сервер.

ID сервера — правый клик по серверу → «Копировать ID» (нужен режим разработчика:
Настройки → Расширенные → Режим разработчика). Это `DISCORD_GUILD_ID`.

### 2. Иерархия ролей — то, обо что спотыкаются все

В настройках сервера роль бота должна стоять **выше** всех ролей, которые он будет
выдавать за ранг. Discord не позволяет управлять ролью, которая выше твоей собственной,
и `/rolemap` предупредит об этом при настройке — но лучше поднять роль бота сразу.

### 3. Заполнить `.env`

```bash
cp .env.example .env
```

Обязательные: `DISCORD_TOKEN`, `DISCORD_APP_ID`, `DISCORD_GUILD_ID`, `DATABASE_URL`,
`REDIS_URL`, `PUBLIC_BASE_URL`. Без любой из них бот не стартует — так задумано, лучше
упасть на старте с понятным текстом, чем посреди работы.

Необязательные, и вот что без них:

- **`STEAM_API_KEY`** ([получить](https://steamcommunity.com/dev/apikey)) — без него `/link steam`
  доходит до входа через Steam, но падает на получении имени профиля. Ранг Dota при этом
  обновляется и без ключа: он приходит из OpenDota, которой ключ не нужен.
- **`RIOT_API_KEY`** ([получить](https://developer.riotgames.com)) — без него не работают
  `/link riot` и обновление рангов LoL и TFT. `/link valorant` работает независимо: там ранг
  вводится руками. Продакшн-ключ выдаётся по заявке с ревью, ключ разработчика живёт 24 часа.

**`PUBLIC_BASE_URL` — не декларация.** `/link steam` строит ссылку на
`{PUBLIC_BASE_URL}/steam/callback` и ждёт, что Steam вернёт туда браузер игрока. На
`localhost` привязка Steam до конца не пройдёт: сама ссылка сформируется, но с интернета
до вашей машины Steam не дойдёт. Для прода это `https://{BOT_DOMAIN}`, куда Caddy сам
получит сертификат — для этого `BOT_DOMAIN` должен быть настоящим доменом, указывающим
на сервер.

### 4. Поднять и зарегистрировать команды

```bash
npm install
npm run db:migrate          # применить миграции
npm run deploy-commands     # зарегистрировать 22 команды на сервере из DISCORD_GUILD_ID
npm run dev                 # или podman compose up -d --build на проде
```

Регистрацию команд надо повторять после каждого обновления, которое добавило команду:
Discord знает тот набор, который ему отправили в последний раз, а не тот, что в коде.

Готово, если `curl localhost:3000/healthz` отдаёт
`{"status":"ok","database":"ok","cache":"ok"}`, а `/ping` в Discord отвечает.

### Локальная разработка

```bash
npm run test:services:up                                 # Postgres на 55432, Redis на 56379
podman exec disbot-test-pg createdb -U bot disbot_dev     # один раз: отдельная база разработки
```

База разработки отделена от `disbot_test` намеренно: `npm run test:int` чистит таблицы
тестовой базы перед каждым файлом и снёс бы данные разработки.

## Бэкап

Работает сам, включён по умолчанию: каждый день в 4 утра `pg_dump` снимает сжатый дамп и
отправляет его **файлом в закрытый канал Discord** `BACKUP_CHANNEL_ID`. Каталог контейнера
обновление бота не переживает — 25 августа 2026 база отказала по квоте, дамп снять было уже
нельзя, и летопись пропала. Канал переживает всё.

1. Создайте текстовый канал, закройте его для `@everyone`, оставьте доступ себе и боту. В
   открытый канал бот дамп не отправит и напишет почему.
2. Дайте боту в канале права «Отправлять сообщения» и «Прикреплять файлы».
3. Пропишите `BACKUP_CHANNEL_ID` и перезапустите бота.
4. Проверьте сразу: `/backup` снимает дамп и отвечает, дошёл ли он.

Если бот ходит в Supabase через transaction pooler (порт 6543), для `pg_dump` нужна отдельная
строка `BACKUP_DATABASE_URL` с session pooler (5432). База больше 10 МБ приходит частями.

```bash
# восстановить (строка есть и в самом сообщении с файлом)
gunzip -c disbot-2026-09-23-0400.sql.gz | psql "$DATABASE_URL"
# если частей несколько — сначала склеить по порядку
cat disbot-2026-09-23-0400.sql.gz.part* > disbot-2026-09-23-0400.sql.gz
```

Отказ бэкапа бота не роняет: причина словами приходит в тот же канал — нет `pg_dump`, нет
прав, версия, пароль. Утром там видно либо файл, либо почему его нет.

Почему это не опция: привязки и ранги подтянутся заново из API игр, а уровни, монеты,
достижения и вся турнирная летопись не восстанавливаются ниоткуда.

## Известное ограничение окружения разработки

На машине, где готовился этот этап, `podman build` работает напрямую, а
`podman compose` — нет: это тонкая обёртка, которой нужен внешний provider-бинарь
(`docker-compose` или `podman-compose`), а ни один из них не установлен. Поэтому
`docker-compose.yml` проверялся сборкой образа (`podman build`) и вручную по
критериям приёмки, а не запуском `podman compose up` локально. Файл рассчитан
на прод-VPS, где provider ожидается установленным — там `podman compose up -d`
должен работать как описано выше. Если после деплоя `podman compose` всё ещё
ругается на отсутствие provider, поставьте `podman-compose` (`pip install
podman-compose`) или `docker-compose` и повторите.
