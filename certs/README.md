# Корневые сертификаты баз данных

Здесь лежат корневые сертификаты удостоверяющих центров, которыми подписаны сертификаты
облачных Postgres. Нужны они для одного: чтобы соединение можно было проверять целиком
(`sslmode=verify-full`), а не только шифровать.

## Зачем это в репозитории

Supabase подписывает сертификат своего pooler собственным центром, а его нет в наборе,
с которым идёт Node. Поэтому `sslmode=verify-full` на её строке подключения отвергается
с `self-signed certificate in certificate chain`, и остаётся выбор из двух:

- `sslmode=no-verify` — шифрование есть, проверки центра нет. Значит, посредник между ботом
  и базой становится возможен: он предъявит свой сертификат, и никто не возразит.
- указать этот центр явно — проверка работает полностью.

Второе честнее, и стоит оно одного файла. Файл лежит в образе, потому что бот подключается
к базе из контейнера, а не с чьей-то машины.

## Как пользоваться

В строке подключения:

```
?sslmode=verify-full&sslrootcert=/opt/app/certs/supabase-ca.crt
```

Путь абсолютный: рабочий каталог процесса задаёт платформа, и относительный искал бы
сертификат там, куда она нас поставит.

## Что здесь есть

| Файл | Кто | До какого срока |
|---|---|---|
| `supabase-ca.crt` | Supabase Root 2021 CA | 26 апреля 2031 |

Взят с `https://supabase-downloads.s3-ap-southeast-1.amazonaws.com/prod/ssl/prod-ca-2021.crt`
— тот же файл, что даёт панель Supabase в разделе Database → SSL Configuration. Обновлять
придётся, когда Supabase сменит центр; признаком будет та же ошибка про цепочку сертификатов.
